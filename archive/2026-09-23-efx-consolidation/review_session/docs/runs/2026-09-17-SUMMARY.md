# EFX TEST tier — 2026-09-17, one page

**Outcome: the TEST tier is live and proven end to end. Nothing in production was touched.**

n8n can now create a hire, run it through ID Setup and IT Setup, and close a JR task, with no
human involved, against a test copy of the system. Roughly 210 calls went through the real chain
with no flaky failures.

---

## What this project actually is

Employee Forms is the set of web forms people fill in to hire, equip, terminate or move someone.
It writes to one spreadsheet and emails the right team at each step.

This work adds a **proper door into that system for n8n**. Today, automation has to imitate a
person: watch for an email, read it, and poke a hidden web address protected by a shared password.
That is how the JR automation works. It is fragile and it fails quietly.

**n8n holds almost none of the logic.** There are 22 items in n8n but 21 are labelled buttons and
one is the door. Every rule — who may do what, what a valid hire looks like, which team is emailed,
how employee numbers are issued — stays in Forms. When those rules change, nothing in n8n changes.

## Four defects found, none catchable locally

All four needed real infrastructure to reproduce. The local suite has no n8n and no Google.

1. **Router response unwrapping.** Read the payload from the wrong field, so *every* call failed
   with a transport error despite Google returning a clean success. Fixed.
2. **Router error codes.** The Router promised that error workflows could read the error code from
   the message. n8n strips it. The code was unreachable from any structured field. Now emitted as a
   tag n8n cannot strip. **Anything branching on error codes must use the new tag.**
3. **Sheet migration grid width.** Apps Script silently widens a sheet; the REST API refuses. A stock
   sheet is 55 columns and the new header goes at 56, so migration failed on every un-migrated
   sheet, production included. Fixed.
4. **IT Confirmation data loss.** The screen loads an editable copy of the original submission, so an
   absent field means "unchanged". The handler instead blanked it. Submitting only the one field the
   contract says is required wiped the employee's name, position, site, manager and ~20 more columns.
   Fixed and re-proven. The dead duplicate handler behind it was deleted.

Two further issues were **found and deliberately not fixed**, because they are production behaviour
needing their own decision: cancelling an already-cancelled workflow silently succeeds again, and the
`specialist` form points at a spreadsheet tab that does not exist.

## Things worth knowing

- **`verified:false` is enforced, not documentation.** The system refuses to automate a form marked
  unsafe and explains why. That gate is what stood between an automation caller and the data loss above.
- **Employee numbering has two parallel series** in the live data, 30k and 151k, which ran side by side
  from March to May. 151k is current. Somebody who knows the history should confirm which continues.
  Test numbering was deliberately started at 500000 so test records are obvious.
- **The bot cannot join a Shared Drive** on a Cloud Identity licence, so the test tier uses its own
  attachment folders. Three settings become mandatory on any tier doing the same.
